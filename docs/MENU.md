# 연금술 메뉴

구매 화면은 실제 메뉴명을 주제목으로 표시하고, 컨셉명은 아래에 회색 보조 글씨로만 표시합니다. 재고 숫자는 숨기며 품절 항목만 회색 처리해 선택을 막습니다. 맛별 상품은 주문·재고·금액을 각각 구분합니다.

| 바람의 정수 | 플레인 휘낭시에 | 2,800원 | 1개 |
| 흙의 정수 | 초코 휘낭시에 | 3,000원 | 1개 |
| 불의 정수 | 카라멜 휘낭시에 | 3,000원 | 1개 |
| 물의 정수 | 무화과 휘낭시에 | 3,400원 | 1개 |
| 고대 마법서 | 로투스 브라우니 치즈케이크 | 3,800원 | 1개 |

휘낭시에 원소 배정과 타르트 구분은 확인한 가안입니다. **도넛 5개 세트는 재고 1단위이며, 승인 시 주사위 1개를 지급합니다.** 이벤트에서 도넛이 당첨될 때도 한 세트를 지급합니다. 주문 내역에는 맛을 구분할 수 있는 실제 메뉴명을 저장합니다.

상품 원본은 `server/catalog.py`입니다. 기존 시연 상품과 다른 번호(101~113)를 사용하여 이전 주문·예판·재고 이력을 보존합니다. 판매 목록과 신규 주문에는 현재 메뉴만 사용합니다. 우유·두유는 구매 주사위를 지급하지 않으며 랜덤 빵 추첨에서도 제외합니다. 기존 예약 수령과 기존 대기 주문 승인·취소는 계속 처리할 수 있습니다.

새 가안은 품목별 현판·이벤트 공용 20단위의 **시연 재고**로 시작합니다. 실제 입고 수량이 아닙니다. 운영용 새 DB는 모든 재고가 0으로 시작하며, 확정된 수량을 담당자가 입력합니다. API 재시작과 메뉴 갱신은 기존 재고를 다시 채우지 않습니다. 이전 버전의 별도 이벤트 재고는 한 번만 현판 재고에 합쳐 총수량을 보존합니다. 추첨 가중치는 남은 현판 재고의 제곱입니다.

우유(112번)·두유(113번)는 별도 품목으로 현판·예판 수량과 수정 이력을 관리합니다. 우유 보상은 두 품목 중 하나를 선택하며, 선택한 품목의 `stock`을 확보합니다. 담당자 승인은 차감을 유지하고 취소는 반환합니다. 인스타 인증은 음료를 직접 지급하지 않습니다. 기존 별도 우유 수량은 최초 시작 시 일반 품목으로 합치고, 이전 수량을 0으로 닫아 중복 이전을 막습니다. 새 로컬 데모는 우유 40개·두유 20개, 새 운영 DB는 모두 0개로 시작합니다.

## 메뉴 이미지와 실물 사진 교체

빵 11종은 `frontend/assets/products/`의 개별 양피지풍 일러스트를 사용합니다. 구매자 메뉴와 담당자 수기판매에 같은 이미지를 표시합니다. [이미지·생성 프롬프트](PRODUCT_ART.md). 이미지가 없거나 불러오지 못하면 중립적인 표시만 남기며 컨셉 아이콘으로 대체하지 않습니다.

1. 사진을 `frontend/assets/photos/`에 넣습니다. JPG·PNG·WebP를 사용할 수 있으며 정사각형으로 준비하면 잘림이 적습니다.
2. `server/catalog.py`의 `PRODUCT_PHOTOS`에 상품 번호와 공개 경로를 등록합니다. 예: `101: '/assets/photos/plain-financier.webp'`.
3. 로컬 API를 재시작하고 확인합니다. 배포 시에는 기존 파이프라인을 사용합니다. 사진을 교체할 때 파일명도 바꾸면 이전 이미지 캐시와 구분됩니다.

API의 `photo`는 메뉴 일러스트 또는 실물 사진 경로입니다. 기존 `image`는 이벤트에서 쓰는 연금술 컨셉 SVG로 별도 유지합니다.
