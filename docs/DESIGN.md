# 화면 구성과 구현 범위

이번 가안은 요청된 구매·이벤트·담당자 기능만 제공합니다. 후기, 퀘스트, 빵 조합, 캐릭터 꾸미기, 공유 카드 등 추가 아이디어는 구현 범위에서 제외합니다.

## 구매자 · 모바일

첫 화면은 이름과 숫자 4자리 비밀번호 입력입니다. 로그인과 계정 만들기를 구분하며, 이미 등록된 이름으로는 새 계정을 만들 수 없습니다. 로그인 이후 상위 메뉴는 **빵 구매 / 이벤트 참여** 두 개뿐입니다.

### 빵 구매

- 현판 구매: 실제 메뉴명·가격·수량 선택 → 선택한 빵과 합계 → 구매 요청 → 담당자 승인 대기.
- 실제 메뉴명을 주제목으로, 컨셉명은 아래에 작은 회색 글씨로 표시합니다. 구매 목록에는 재고 숫자나 컨셉 아이콘을 표시하지 않습니다. 왼쪽에는 실물 사진 자리를 두고 사진 등록 전에는 중립적인 빈 이미지 영역을 표시합니다. 품절 항목만 회색 처리하고 수량 버튼을 비활성화합니다.
- 예판 수령: 로그인한 이름과 예약 전화번호로 조회 → 예약 빵 확인 → 수령 요청 → 담당자 승인 대기.
- 주문 내역: 대기·수령 완료·취소 상태와 금액을 표시합니다. 승인된 주문에서 이벤트 화면으로 이동할 수 있습니다.
- 우유는 2,000원으로 함께 판매하며 ‘주사위 미지급’을 표시합니다. 주문 금액·수량에는 포함하지만 구매 주사위는 빵 수량만 계산합니다.
- 구매 화면에는 점수 카드, 주사위, 순위, 뽑기 화면을 표시하지 않습니다.

### 이벤트 참여

- 이벤트는 **점수·주사위·순위를 한 페이지**에 표시합니다. 별도 주사위 탭은 없으며 기존 `#dice` 주소도 `#ranking`으로 연결합니다. 양일 누적 상위 3명과 본인 위·아래 최대 두 명을 표시하며 날짜가 바뀌어도 자동 초기화하지 않습니다.
- 상단 개인 카드에 캐릭터·현재 점수·다음 보상 목표, 남은 주사위와 큰 동작 버튼을 모읍니다. 주사위가 있으면 보라색 **주사위 1개 굴리기**, 없으면 같은 자리에 노란색 **빵 구매하고 주사위 얻기** 버튼을 표시합니다. 굴리기는 화면 이동 없이 실행하고 결과를 버튼 위에 표시합니다.
- 넓은 화면은 개인 카드 옆에 순위를, 모바일은 개인 카드 아래에 순위를 표시합니다. 캐릭터 성장 단계와 당첨 기록은 접어서 표시합니다. 순위를 불러오는 중에도 주사위를 굴릴 수 있습니다.
- 빵 구매 1단위당 주사위 1개이며 우유는 제외합니다. 도넛은 5개 한 세트를 1단위로 취급합니다. 서버에서 공정하게 1~6을 뽑고 해당 값만큼 점수를 더합니다.
- **10점마다 랜덤 빵 1개**를 받습니다. 다음 목표까지 **‘N점 더 모으면 레벨업!’**을 표시합니다. 최고 레벨 이후에는 기존 빵 보상 안내를 표시합니다. 결과를 클라이언트에서 조작하지 않습니다.
- 목표에 도달하면 **‘레벨업하고 빵 받기’** 버튼을 표시합니다. 주사위를 굴려 목표를 넘으면 같은 안내를 팝업으로 엽니다. 점수만으로 캐릭터가 바뀌지는 않습니다. 버튼을 눌러 빵 지급이 성공해야 성장하며, 재고가 없으면 성장과 보상 자격 모두 유지합니다.
- 미획득 캐릭터 자리는 물음표로 표시합니다. 첫 캐릭터를 얻기 전의 대표 자리와 앞으로 받을 단계도 동일하며, 레벨업 안내 팝업에서는 새 캐릭터의 모습·이름을 미리 공개하지 않습니다. 빵 보상 지급이 성공하면 해당 캐릭터를 보여줍니다.
- 캐릭터 가안은 저장소의 SVG로 만들었으며, 0점 수련생 → 10점 견습 연금술사 → 20점 원소 연금술사 → 30점 황금 연금술사 → 40점 별빛 현자 → 50점 전설의 대연금술사입니다. 점수를 한꺼번에 넘겼다면 버튼을 단계별로 눌러 보상을 받습니다.
- 50점 이후에는 최종 캐릭터를 유지하고 **‘빵 보상 받기’**로 60·70·80점… 보상을 계속 받습니다. 점수와 순위는 계속 누적됩니다.
- 판매 가능한 현판 재고의 제곱에 비례해 추첨하며 당첨 시 현판 재고에서 1단위를 차감합니다. 확률 설명은 구매자 화면에 표시하지 않습니다.
- 실제 상품 지급과 최종 순위 시상은 현장에서 처리합니다.

## 담당자 · 노트북

상단에 **주문 확인 / 수기 판매 / 재고 / 인스타 이벤트 / 인수인계** 다섯 메뉴만 표시합니다. 현판 판매 가능 수량과 예판 보관 수량은 모든 담당자 화면 상단에 표시합니다. 예판 보관에는 승인 전 수령 요청된 빵도 포함됩니다. 각 화면의 기능 설명은 접어서 표시합니다.

| 화면 | 기능 |
| --- | --- |
| 주문 확인 | 예판·현판 이름, 빵·수량, 합계, 승인·취소. 이름·예약 전화번호·메뉴 검색과 주문 상태 필터. 새 주문은 자동 표시 |
| 수기 판매 | 현장 구매 / 예약한 빵 수령 선택. 현장은 구매자·수량·합계 입력 후 판매 완료, 예약은 이름·전화번호 일부·메뉴 검색 → 예약 확인 → 수령 계정 선택·승인 |
| 재고 | 빵·우유를 같은 표에서 관리. 현판·이벤트 공용 / 예판 / 접수 보관 수량, 수량 증감과 사유, 변경 이력, 예판 예약 등록, 버튼으로 펼치는 예판 수령 현황 |
| 인스타 이벤트 | 등록 사용자 선택 → 인증 완료. 주사위 1개·우유 1개 지급을 기본 체크하고 각각 해제 가능. 두 항목 모두 해제하면 인증만 기록. 참여·빵 당첨 기록 |
| 인수인계 | 전임자 메모, 메모 작성, 담당자 시간표 |

예판 예약 등록은 이름·전화번호·빵 수량을 입력하는 폼입니다. 운영 화면에 JSON이나 빵 ID 입력을 요구하지 않습니다. 별도의 통계 홈, 홍보 배너, 독립 이용 가이드 메뉴는 두지 않습니다.

수기 판매의 **예약한 빵 수령**에서는 예약 당시 품목·수량·금액을 그대로 보여주며, 수량을 새로 입력하지 않습니다. 미접수 예약은 **기존 계정에 추가 / 새 계정 만들기**를 선택합니다. 기존 계정은 담당자가 구매자 목록에서 선택하며 예약자 이름과 계정 이름이 달라도 연결할 수 있습니다. 주사위와 주문 내역은 선택한 계정에 추가되고 원래 예약자 정보는 유지합니다. 새 계정은 예약자 이름과 숫자 4자리 비밀번호로 만들고 담당자가 비밀번호를 구매자에게 알려줍니다. 이미 접수된 수령 요청은 연결된 계정과 같은 주문으로 승인합니다. 완료한 예약은 수령 계정과 완료 내역만 표시하고 재승인 버튼은 숨깁니다.

관리자 검색은 예판 현황·예약 수령·주문 확인에만 표시합니다. 이름·전화번호 일부(끝자리 포함)·메뉴로 검색하며, 전화번호의 하이픈·공백은 무시합니다. 여러 단어를 입력하면 모두 포함된 항목만 표시합니다. 수령 화면은 검색 결과의 **예약 확인** 버튼을 눌러 서버의 최신 내역과 수령 상태를 가져온 뒤 승인합니다. 다른 예약을 검색하면 이전 선택과 진행 중인 조회 결과를 초기화합니다. 기존 계정은 이름으로 검색해 목록을 좁힐 수 있으며, 계정 검색어를 변경하면 이전 계정 선택을 해제하므로 수령 계정을 다시 선택해야 합니다. 검색어와 펼친 현황은 자동 갱신 후에도 유지하고 입력 중에는 포커스를 바꾸지 않습니다. 구매자 화면과 인증·승인 API는 변경하지 않습니다.

재고의 **예판 수령 현황** 버튼은 처음에는 접혀 있습니다. 펼치면 검색창과 이름·전화번호·메뉴·수령 상태 표를 보여줍니다. 메뉴는 ‘플레인 휘낭시에 2개, 초코 휘낭시에 1개’처럼 한 셀의 줄글로 표시하고, 상태는 수령 대기 / 수령 요청 접수 / 수령 완료로 구분합니다. 검색 결과가 없으면 안내를 표시하고 검색어를 지우면 전체 목록으로 돌아갑니다. 승인·취소 결과를 자동 갱신하며 표를 펼친 상태는 유지합니다.

## 디자인팀 주사위 애니메이션 요청

현재는 임시 CSS 애니메이션입니다. 필요한 상태는 굴리기 전 / 굴리는 중 / 1~6 결과 / 주사위 없음 / 목표 달성 / 보상 소진입니다. 서버가 확정한 숫자를 표현하고 결과 숫자·점수는 텍스트로도 보여줍니다. 모바일 시안과 주사위 면 6종, 시작·종료 시점, 파일 형식·용량을 정하면 교체합니다. 동작 줄이기 설정에서는 애니메이션을 생략합니다.

## 저장소와 실행 환경

Cloudflare Pages와 Oracle Quick Tunnel 구성은 유지합니다. DB 쓰기 잠금과 재고·승인 중복 방지는 기존 API에서 처리합니다. PostgreSQL 어댑터도 공통 쓰기 잠금을 지원합니다. 현재 공개 가안은 별도 SQLite 샘플 DB를 사용하며, 이번 화면 정리에서 DB 엔진 전환이나 샘플 데이터 초기화는 하지 않습니다.
