# 행사 초기화와 예판 CSV 등록

**초기화 → 관리자 화면에서 총재고 입력 → CSV 예판 등록** 순서로 진행합니다. 두 도구는 현재 운영 중인 SQLite용입니다. 실데이터 CSV는 Git에서 제외되는 `data/` 안에 둡니다.

## 1. 운영 기록 초기화

기존 DB의 `DB_PATH`를 지정합니다. 운영 서버에서는 두 도구에 `--env-file /etc/bbang-palja/api.env`를 추가합니다. 미리보기의 `database`가 대상 DB인지 확인하세요.

```bash
export DB_PATH="$PWD/data/shared-inventory-preview.sqlite3"
export DATABASE_URL=''
python3 ops/reset-db.py --event --check
```

초기화 실행 시 API와 해당 DB를 사용하는 자동 배포·백업 작업을 잠시 중지합니다.

```bash
python3 ops/reset-db.py --event --yes
```

- 보존: 시간표, 메뉴·가격, 배지·칭호 정의, 이벤트 음료 한도 등 설정. 공용 비밀번호·서버 환경 파일도 유지합니다.
- 두 도구는 카탈로그 동기화를 실행하지 않습니다. API 시작 시 메뉴·가격을 코드의 카탈로그로 동기화하는 기존 동작은 같습니다.
- 삭제: 구매자·담당자 계정, 세션, 주문·예판·판매·이벤트, 주사위·점수·보상·획득 기록, 재고 이력, 메모·알림.
- 모든 빵·음료·오트밀 재고는 0이 되고, 이벤트 음료의 누적 사용량도 비워집니다. 담당자는 공용 비밀번호로 다시 로그인합니다.
- 변경 전 DB를 `DB_PATH` 폴더의 `backups/before-reset-*.sqlite3`에 백업하고 무결성을 확인합니다. 삭제는 한 트랜잭션으로 처리하며 실패하면 취소합니다. 알 수 없는 테이블이 있으면 중단합니다.

`--event` 없는 기존 `--yes`는 DB 전체 재생성입니다. 시간표를 보존하는 행사 준비에는 **반드시 `--event`를 사용합니다.**

## 2. 관리자 화면에서 재고 입력

API를 다시 시작하고 **재고관리 → 재고 수정**에서 예판을 포함한 품목별 총재고를 입력합니다. 우유·두유·오트밀과 이벤트 음료 제공 한도도 여기서 관리합니다. 스크립트는 초기 수량을 입력하지 않습니다.

## 3. 예판 CSV 등록

UTF-8 CSV 첫 행은 `이름,연락처,메뉴별 수량`입니다. 필요한 메뉴 열만 넣을 수 있으며, 열 순서는 자유입니다.

```csv
이름,연락처,휘낭시에(플레인),휘낭시에(카라멜),휘낭시에(초코)
김나나,010-0000-0001,1,2,0
이테스트,01000000002,0,0,1
```

메뉴: `휘낭시에(플레인/초코/카라멜/무화과)`는 맛별로 한 열씩, `다쿠아즈(레몬)`, `다쿠아즈(얼그레이)`, `보늬밤 마들렌`, `로투스 브라우니 치즈케이크`, `글레이즈드 도넛`, `에그타르트`, `치즈타르트`, `우유`, `두유`. 사이트에 표시되는 메뉴 이름도 사용할 수 있습니다. 도넛은 **5개 한 세트가 수량 1**입니다.

- 전화번호는 `010NNNNNNNN` 또는 `010-NNNN-NNNN`. 끝에 대시가 더 붙으면 오류입니다. 위 번호는 로컬 테스트용입니다.
- 수량은 0~100 정수, 빈칸은 0입니다. 한 예약의 합계는 1~100개, 파일은 1~500건입니다.
- 같은 이름·연락처의 중복은 파일 안과 DB 모두에서 거절합니다. 합치거나 건너뛰지 않습니다. 동일 이름이라도 번호가 다르면 별도 예약입니다.
- 신청 순서대로 행을 둡니다. 이 순서가 예판 선착순 보상에 사용됩니다.

```bash
# 기본: 검증·필요 재고·합계만 확인
python3 ops/import-preorders.py data/preorders.csv
# 실제 등록
python3 ops/import-preorders.py data/preorders.csv --apply
```

등록 시 현재 DB 가격을 예약 가격으로 저장하고 현판 가능 재고를 예판 재고로 이동합니다. 총물량을 늘리거나 계정·판매·주사위를 생성하지 않습니다. 구매 승인 시 기존 규칙으로 주사위가 지급됩니다. 재고 부족·잘못된 행·중복이면 일부만 등록하지 않습니다. 재고 부족의 종료 코드는 2, 다른 입력 오류는 1입니다.

## 더미 CSV로 전체 흐름 검증

```bash
python3 ops/test-event-preparation.py
```

매번 `data/event-preparation-tests/run-*/`에 새 DB·더미 CSV·초기화 전 백업을 만듭니다. 기존 로컬·운영 DB와 원본 CSV는 사용하지 않습니다. 임시 localhost 포트에서 테스트를 실행한 뒤 서버는 종료합니다.

검증: 시간표·가격 보존, 운영 기록·재고 초기화, 관리자 API 재고 입력, CSV 미리보기·4건 등록, 재실행 중복 방지, 이름이 같은 다른 번호의 예약 조회·수령, 일반·무지개·은색·금색 예판 주사위의 승인 후 지급. HTTP 기록은 stderr, 결과·생성 파일 경로는 stdout JSON으로 출력합니다.
